# 内网AI基础设施的几个小目标

> 本篇由 GLM-5.3-flash 生成，所以就不需要 GLM 5.1 再来勘误了，你们同行之间互相关照吧。

最近半年家里的开发模式基本定型了：模型调用走聚合网关，日常任务丢给各式 agent 去跑，人在旁边钓鱼验收。但跑着跑着就发现，内网里的东西多起来之后，乱也跟着多起来。各家模型 API 一套协议，agent 各写各的工具调用，服务互相不认识，谁在什么端口上跑着什么全靠脑子里记。更要命的是某天发现一个 agent 自作主张干了件我不太希望它干的事，而我毫不知情。

于是觉得该认真规划一下内网的 AI 基础设施了。目标不多，五件事，按依赖关系正好一层一层摞上去。

### 第一层：模型 API 聚合网关（已实施）

这是地基。各家供应商的 API 协议、计费方式、限流策略、密钥体系都不一样，每写一个新项目就要重新对接一遍，纯属浪费生命。

所以先做了个聚合网关：对外统一成一套兼容协议，对内接各家供应商，统一管理密钥、记账、配额。哪个项目用了多少 token，花了多少钱，一查便知。模型换了、供应商换了，下游项目无感。

这一层已经实施完毕，用下来没什么大问题，算是整个体系里唯一让人省心的部分。后面的所有 agent 都默认从这里取模型能力。

### 第二层：服务发现协议

agent 要干活，第一件事是知道内网里有什么可用的。现在我的做法是：想起来的时候去翻笔记，翻不到就去翻端口。这显然不体面。

我的设想是让每个服务自带发现协议：服务启动时在网内宣告自己，宣告内容不只是"我在 192.168.x.x 的 8848 端口"，而是一份机器可读的名片——我叫什么、我提供哪些能力、每个能力的入参出参、一句话简介。挂了就注销，活着就续期。有点像 mDNS，但携带的是给 agent 读的语义信息，而不是给打印机读的。

这样一来，任何 agent 进入内网，先做一次发现，就能拿到一张实时更新的服务目录。服务之间也不用互相硬编码地址了。目录和简介本身就是提示词的一部分，agent 感知环境的方式从"运维口口相传"变成了"自带说明书"。

### 第三层：小型 agent 内核

现在的问题是每写一个带 agent 能力的东西，就要把工具调用循环、上下文管理、重试、记忆这些轮子重造一遍，造得还都不太一样。

所以想抽一个小型化的 agent 内核出来，做成基础库。功能刻意保持最小：对话循环、工具调用、上下文压缩、会话持久化，外加对接第一层的网关。内核不绑定任何业务，一个项目引入这个库，就天然长出了 agent 能力，剩下的精力都花在业务工具的实现上。

小是关键。内核越大越难维护，越没人敢引入。它应该像个垫片，而不是个框架。

### 第四层：设备级 agent

有了内核，就可以在每个设备上放一个独立执行的 agent，作为这台机器的管家。它管理编排本机服务：起停、监控、部署、看日志，服务的元数据通过第二层的发现协议对外宣告。

这个角色有点像 AI 版的 systemd，但它是个能听懂人话的 systemd。我对着它说"把下载站的旧任务清一清，顺便看看磁盘是不是又满了"，它自己拆任务、调工具、汇报结果。设备与设备之间的 agent 通过发现协议互相认识，跨设备的活儿也能互相搭把手。

### 第五层：统一通知与授权中心

这是整个体系里我认为最重要、也最"保命"的一层。

前四层解决的都是"效率"问题：模型怎么统一拿、服务怎么被发现、agent 怎么生出来、活儿怎么被编排。但 agent 多了之后，真正麻烦的是"边界"问题：agent 干了不该干的事怎么办？

我的设想是搭一个统一的通知和授权中心，配上简单的认证机制，规则大概是这样：

1. 每个 agent 在授权中心注册身份，领到自己的凭证。从此它是谁、它能干什么，都有据可查。
2. agent 平时在自己的权限范围内自由行动。但凡要越界——删文件、动网络配置、花超过某个额度的钱、在生产路径上执行写操作——必须先向授权中心发起申请。
3. 授权中心把申请推送给我，我点头，它才放行；我摇头，agent 拿着拒绝原因回去重新规划。审批支持延迟处理，agent 排队等着，等我钓鱼回来一次性处理。
4. 所有越界行为的最终实施结果，无论成败，都要回报到通知中心。我宁可被通知轰炸，也不能接受"它偷偷干了"。

本质上这就是给内网里所有 agent 建了一套"行为许可证"制度。效率上限靠前四层，安全下限靠第五层。

### 尾巴

五层摞下来，大概是这么一张图：网关供能力，发现协议供认知，内核供个体，设备 agent 供组织，授权中心供秩序。

目前只有第一层是完工的，剩下四层还是 PPT 状态。按依赖顺序，接下来大概率先动第三层的内核——因为第五层的授权机制，说到底也是内核里长出来的一个回调点。第二层和第四层可以边做内核边顺手带上。

等这套东西跑顺了，我大概就真的可以从"运维我自己"这件事里退休了。
